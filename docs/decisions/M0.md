# Décisions d'exécution du jalon M0

Ces décisions précisent ou amendent les ADR pour l'exécution de M0. Les renvois vers `review/…` restent en texte : documents de revue non publiés.

## Décisions

1. **Compte du porteur, pas d'organisation.** Dépôt sous le compte `Themlaw`. Pas de merge queue. Ruleset de `main` : PR obligatoire, `ci-success` requis, historique linéaire, squash, pas de force-push, pas de suppression. `CODEOWNERS` : `* @Themlaw`. L'image `ghcr.io/themlaw/shelfhold` est définie à un seul endroit (`env.IMAGE` des workflows) plus le `compose.yaml` d'exemple. Le pseudo `Themlaw` est autorisé dans les fichiers publics (URL du dépôt) ; tout autre détail d'infrastructure personnelle reste interdit. Amende ADR-0016 ; l'organisation viendra plus tard (ADR-0019).
2. **Releases.** Release par `gh release create` puis retag de l'image sur `release: published` (`docs/releasing.md`) ; release-please est abandonné (O1, O2). Ruleset des tags `v*` : ni suppression ni mise à jour, création autorisée.
3. **Workflow réutilisable.** `release.yml` appelle `image.yml` (`workflow_call`), aussi appelé par `ci.yml`.
4. **Liste de noms interdits.** Stockée dans le secret `DENYLIST_NAMES`. Sur une PR de fork (secret absent), le job est sauté avec avertissement et relancé avant fusion.
5. **Hors périmètre M0.** Le job `golden` existe mais reste vide jusqu'à M1a. Le contrat Suwayomi S5 tourne dans `contract.yml` (`workflow_dispatch` et hebdomadaire) dès M0 : Suwayomi épinglé, source locale seule, aucun dépôt d'extensions, sortie réseau bloquée. `kavita-routes` arrive en M1a.
6. **Publication.** ADR 0001 à 0051 dans `docs/adr/`, spécification dans `docs/spec/`. Jamais de dossiers de recherche, de revue ou de notes privées.
7. **Compose d'exemple.** Tag `edge` en M0 ; `0.x` à partir des releases.
8. **Temps.** Les boîtes de temps en heures sont converties en « effort agent », suivi dans `docs/governance/velocite.md`.
9. **ENF-GOV-006.** Relevé de départ documentaire ; entretiens reportés (dépendent du porteur) ; porte P0 jugée sur S1, S2, S4, S5 et la veille concurrente documentaire. L'exigence est déclarée PARTIELLE.
10. **Versions des spikes (S2).** Vérifiées au moment du spike, dernière version stable âgée d'au moins 14 jours. Le code des spikes est retiré du dépôt ; seuls `RESULTATS.md` et les `results.json` restent.
